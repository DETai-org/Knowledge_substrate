## Правила работы со ссылками на базу знаний (MkDocs)

Если в файлах репозитория встречается ссылка на документацию в формате публичного URL MkDocs (https://detai-org.github.io/), агент может получать её содержимое двумя способами: открывая страницу по указанному адресу или обращаясь к соответствующему файлу внутри репозитория.\
Поскольку база знаний MkDocs собирается из файлов, находящихся в папке `knowledge_core/source_of_truth/docs/ecosystem/`, такую ссылку можно рассматривать как указатель не только на внешнюю веб-страницу, но и на путь к документу внутри этой папки, при сохранении остальной структуры URL.
Рекомендуется использовать тот способ доступа, который в конкретной ситуации оказывается быстрее и продуктивнее для получения нужной информации.

## Локальный просмотр ветки или Pull Request в MkDocs

Фразы пользователя **«Подними MkDocs на текущей ветке»** и **«Покажи локально PR №…»** являются запросом на локальную визуальную проверку документации.

Перед переключением проверь `git status --short`. Не перезаписывай незакоммиченные пользовательские изменения: если рабочее дерево занято другой работой, используй отдельный `git worktree` или остановись и согласуй переключение.

Для просмотра Pull Request в чистой рабочей копии:

```powershell
gh pr checkout <PR_NUMBER>
py -m pip install -r requirements-docs.txt
py -m mkdocs serve --dev-addr 127.0.0.1:8000
```

Если локальная ветка PR уже существует, достаточно переключиться на неё и подтянуть изменения:

```powershell
git fetch origin
git switch <BRANCH_NAME>
git pull --ff-only
py -m mkdocs serve --dev-addr 127.0.0.1:8000
```

После запуска открой `http://127.0.0.1:8000/Knowledge_substrate/` и сообщи пользователю имя ветки, commit и прямую ссылку на проверяемую страницу. Если порт `8000` занят, сначала установи, что его использует MkDocs именно этого репозитория; не останавливай посторонний процесс. После смены ветки перезапусти сервер, чтобы сайт был собран из нового состояния.

На macOS и Linux используй `python -m ...` вместо Windows launcher `py -m ...`. Локальный сервер является только предпросмотром: он не публикует draft на основном сайте.

## Правило внесения правок в документы экосистемы

Если задача требует добавить, изменить или уточнить файлы внутри `knowledge_core/source_of_truth/docs/ecosystem/ru/ecosystem/*`, правки сначала вносятся в сборочную ветку `docs/ecosystem` и публикуются через актуальный pull request `docs/ecosystem → main`.

Не вносить такие изменения напрямую в `main`: сначала переключиться на `docs/ecosystem`, перенести или выполнить правки там, а уже затем готовить их к публикации через соответствующий pull request.
