# 🤝 Взаимодействие с Codex / GPT

Хорошая задача для Codex не обязана быть написана техническим языком. Достаточно ясно передать цель, доступный контекст, важные ограничения и способ проверки результата. Остальное можно уточнить в диалоге.

Текущая командная организация разработки описана в [Work Model](../../DETai/U.L.I/3_Technical_Standards/work-model/work-model.md).

## 🎯 Что полезно сообщить в начале

- какой результат нужен;
- в каком проекте или документе ведётся работа;
- что нельзя менять;
- какие примеры, ссылки или скриншоты отражают ожидание;
- как понять, что задача выполнена.

## 🧭 Как Codex получает контекст

Codex читает разговор и доступные файлы проекта. Репозиторный `AGENTS.md` задаёт локальные правила, маршруты к знаниям и ограничения. Для повторяемого процесса могут подключаться [Codex Skills](codex-skills.md).

Контекст не следует считать безграничным: если важное решение находится в другом репозитории, закрытом сервисе или старом разговоре, на него нужно дать ссылку либо предоставить доступный источник.

## ⚠️ Частые ошибки

- **Нет проверяемого результата.** Просьба «сделай лучше» требует уточнить, что именно должно стать лучше.
- **Перепутан путь или имя файла.** Регистр, пробелы и точное расположение имеют значение.
- **Используется `AGENT.md` вместо `AGENTS.md`.** Codex ищет файл с именем `AGENTS.md`.
- **Не обозначены границы.** Без них локальная правка может незаметно превратиться в изменение архитектуры.
- **Результат не проверен.** Изменённый файл ещё не означает работающую систему — нужна подходящая сборка, тест или визуальная проверка.

## ✅ Простая формула

```text
цель + контекст + ограничения + проверка = понятная задача для Codex
```

Для сложных межсистемных задач используйте [формат взаимодействия](codex-interaction-format.md), а способ исполнения согласуйте с Work Model.
