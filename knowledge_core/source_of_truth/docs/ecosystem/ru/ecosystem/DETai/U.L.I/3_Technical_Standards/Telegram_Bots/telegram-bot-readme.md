# README для Telegram-бота

**Функция:** `guide`. README — это **карта реальной структуры приложения**, а не второе описание продукта, перечень будущих функций или протокол прошлых релизов. Путь и ссылка должны соответствовать существующему файлу или каталогу. Пример подходит и для Aiogram, и для TypeScript.

## Минимальный шаблон корневого README

````markdown
# <Название бота>

Кратко: назначение приложения и роль в экосистеме (1–2 предложения).

Публичное объяснение → [Knowledge Substrate](<действующая ссылка>).
Задачи и рабочая история → [Team OS](<ссылка на проект>).

## Где что находится

| Что ищем | Источник |
| --- | --- |
| Конфигурация экземпляров и режимы | [config/README.md](config/README.md) |
| Входной допуск и доверенные пользователи | [config/README.md](config/README.md) |
| Сервисные контракты и интеграции | [docs/README.md](docs/README.md) |
| Реализация и структура обработчиков | <ссылка на реальную папку кода> |
| Локальный запуск и тесты | <ссылка на действующий guide> |
| Production deploy | <ссылка на действующий runbook> |

## Границы

Кому принадлежат: Identity, продуктовые права, данные, очередь, платежи.
Не копировать в README реальную тарифную матрицу, токены и живые IDs людей.
````

**Важно:** пример — не готовые ссылки для любого репозитория. Если `docs/`, `config/README.md`, тестов или deploy-каталога пока нет, их **не следует выдумывать ради шаблона**. Уберите лишнюю строку или создайте действительно необходимый файл и загрузчик в одном изменении.

## README внутри папки `config/`

Минимально: таблица `файл → что задаёт → кем реально читается`, ссылка на [стандарт конфигурации](configuration-standard.md), имя профиля, правило получения секретов и источник текущих live-значений. Конфигурационный README не должен переписывать список пользователей, токены или значения из JSON. Если режим/допуск загружается через ENV, нельзя одновременно объявлять неиспользуемый JSON действующим — требуется явная миграция с одним итоговым источником.

## Документы разных жизненных циклов

- **README** отвечает «где искать». Публичная справка и общие технические стандарты — в Knowledge Substrate.
- **Policy/standard** отвечает «что обязательно и почему это право/формат». **Runbook** — «как безопасно выполнить действие». **ADR** — короткая запись принятого и отвергнутого решения.
- **Team OS** хранит задачи, будущие изменения и журналы выполненной работы. Утверждения `TBD`, старые списки незавершённых этапов и неподтверждённые номера релизов не должны жить в постоянном README.
- Системные переменные, пути и Bot ID не обязательно секреты, однако реальные токены/пароли/ключи — **вне Git**. Версия продукта определяется выпущенными артефактами и Git tags, а не заголовком, который никто не обновляет.

См. [общий стандарт создания Telegram-бота](telegram-bot-creation-standard.md), [стандарт конфигурации](configuration-standard.md) и [функции документов DETai](https://docs.detai-x.com/ru/ecosystem/Management_layer/Docs-Ecosystem/functions_of_documents/).
