# Рабочая среда участника

Рабочая среда — ролевой маршрут по нескольким системам, а не новый общий контейнер. Она помогает понять, куда идти с конкретным вопросом, не перенося знания из их канонических домов.

| Мне нужно | Основной контур | Почему именно там |
|---|---|---|
| Понять смысл, архитектуру или действующее правило | Knowledge Substrate | канонические объяснения, policies, standards и связи |
| Увидеть приоритет, задачу, срок и ответственного | Management runtime / task system | текущее исполнение и координация |
| Создать или проверить технологическое решение | U.L.I. и GitHub | код, технические контракты, review и release evidence |
| Понять пользовательский продукт | owning product node / Platform DETai | charter, user docs, intended use, Trust и lifecycle |
| Увидеть роли и подтверждённый вклад | Team OS / Contribution Ledger | роли, события, результаты и история ответственности |
| Найти runtime-данные или права доступа | соответствующий runtime | действующее состояние, а не документационная копия |
| Найти договор, cap table или финансовый оригинал | Corporate Vault | ограниченный юридический и финансовый контур |
| Увидеть публичное представление | основной сайт DETai | объяснение, визуализация, продукт и маршрут действия |

## Базовый путь новой работы

1. Найти систему и канонический контекст в Knowledge Substrate.
2. Проверить роль, полномочия и ожидаемый результат.
3. Выполнять работу в owning runtime, репозитории или task system.
4. Связать результат с задачей, решением и evidence.
5. Вернуть устойчивое новое знание в канонический дом через review.

Инструмент не определяет архитектуру. ClickUp не является Governance, GitHub не является U.L.I. целиком, а MkDocs не является runtime всей экосистемы.
