# Данные участника Team OS: видимость, AI и публикация

**Базовый принцип:** вступление в команду, заполнение анкеты и подключение AI-плагина **не являются согласием на публикацию сведений в интернете**. Внутренний доступ, доступ AI и две публичные страницы — разные решения.

Документ закрепляет **согласованную целевую политику**. Индивидуальные разрешения Web/Core/MCP выпущены 14 октября 2026 года в Team OS #105/#106. Изменения renderer и JSON-LD публичного сайта остаются отдельным выпуском Sites #608. [Практическое руководство](public-profile.md) описывает существующий flow публикации; [правила доступа](access.md) — действующие роли.

## Четыре поверхности, две пары

| Закрытый редактор | Возможное публичное представление | Смысл |
| --- | --- | --- |
| **Team OS** — внутренний профиль, Home и рабочие данные | **Team Profile**: `/ru/about/name-surname` | Человек как участник команды DETai |
| **DETai Account** — личный кабинет | **Personal Profile**: `/ru/@username` | Человек сам по себе, его профессиональные сведения и выбранные результаты |

Это **один Account и одна личность**, но разные контексты. Team OS Member отражает членство, DETai Identity — учётную запись. Сайт отображает разрешённые проекции и не становится самостоятельным хранилищем анкет.

Personal Profile — пока ранняя beta-поверхность с ограниченным редактированием и `noindex`. `Noindex` не означает конфиденциальность: содержимое, доступное по URL, может увидеть посетитель. Автоматической синхронизации публичных полей Team OS с Personal Profile сейчас нет; не обещать её в UI.

## Обязательность и разрешения

**Обязательно** — для сохранения внутреннего профиля; **очень желательно** — рекомендовано без блокировки; **по желанию** — полностью добровольно; **системное** — создаётся при работе. AI — не самостоятельная публичная аудитория: это разрешённые Core данные от имени пользователя, запрошенные для конкретной работы.

| Поле | Заполнение | Командный доступ | AI через MCP | Team Profile | Personal Profile |
| --- | --- | --- | --- | --- | --- |
| Моя роль в команде DETai | **Обязательно** | Да, по правам | Да, по правам | **Обязательно при добровольной публикации** | Не переносить автоматически |
| Чем я занимаюсь в DETai | **Обязательно** | Да, по правам | Да, по правам | **Обязательно при добровольной публикации** | В будущем — по выбору |
| Мои проекты и вклад в DETai | **Очень желательно** | По правам | Краткое разрешённое резюме | По выбору | В будущем — по выбору |
| Фото | **Очень желательно** | По правам | По необходимости | **Обязательно для новой полной Team Profile** | По отдельному согласию |
| Профессиональная биография | По желанию | По правам | Не по умолчанию | По выбору | В будущем — по выбору |
| Интересы и специализация | **Очень желательно** | По правам | Только по необходимости | По выбору | В будущем — по выбору |
| Образование и квалификация | По желанию | По правам | Не по умолчанию | По выбору | В будущем — по выбору |
| Соцсети и профессиональные ссылки | По желанию | По правам | Не по умолчанию | По каждой ссылке | В будущем — по каждой ссылке |
| Мои ценности и принципы | По желанию | **Только владелец по умолчанию**, команде — по отдельному выбору | Отдельное `useInAi` + ACL | Нет автоматически | Нет автоматически |
| Мой рабочий фокус | **Очень желательно** для активной работы | Только владелец | При `useInAi` для нужного target | Нет | Нет |
| Инструкции «Как GPT лучше со мной работать» | По желанию | Только владелец | При `useInAi` | Нет | Нет |
| Контрольные точки | Системное | Только владелец | Только разрешённый контекст | Нет | Нет |
| Tasks, Notes и WorkLogs | Системное | По объектным правам | По объектным правам | Не автоматически | Не автоматически |

**Обязательное внутри команды ≠ публичное по умолчанию.** Человек вправе работать без публичной страницы. Для новой **полной** Team Profile он добровольно соглашается на обязательный публичный минимум: роль, описание деятельности, фото. Отсутствие фото не блокирует сохранение внутреннего профиля; проверка нужна в **Core при публикации**, а не только в Web.

Минимальный **авторский** профиль имеет отдельное согласие и lifecycle — не ломать его существующее поведение новым правилом полной Team Profile без отдельного решения. Старые опубликованные страницы без фотографии требуют контролируемого review, а не молчаливого отзыва старого согласия.

## Публикация и выбор полей

Публикация полной Team Profile возможна только после явного согласия **самого участника**. Manager вправе помочь заполнить данные, но не вправе включать согласие за человека.

Помимо обязательного минимума, участник отдельно выбирает, какие сведения о проектах, профессиональных интересах, биографии и образовании выводить на командную страницу. Появление нового поля **не расширяет прежнее согласие** автоматически.

У одной социальной ссылки хранится один URL. Для неё нужны независимые назначения: **«Показывать на странице команды»** и в будущем **«Показывать в личном профиле»**. Пока Personal Profile не поддерживает такую запись, не изображать его переключатель как действующую функцию. Ссылка без публичного разрешения остаётся внутри разрешённого командного контура. Никакое общее согласие не должно скрытно публиковать все заполненные соцсети.

Полная публичная страница и авторская подпись в блоге имеют разные согласия. Отзыв разрешения и offboarding должны использовать существующий безопасный workflow изменения публичной проекции; сохранённый профиль и публикация после GitHub PR / production deploy — **разные состояния**. Git history, архив и уже существующие копии в поисковиках не исчезают мгновенно.

## Фокус, принципы и персональные инструкции остаются в Home

- **Ценности и принципы** — долгоживущие записи. Новый профиль принципов получает аудиторию **«Только вы»** по умолчанию. «Видно команде» включается **явно**, независимо от переключателя «GPT учитывает ваши ценности и принципы». Для AI необходимы `useInAi` и фактический ACL. Ранее сохранённые `teamDomainIds` и `useInAi` **не изменять автоматически**.
- **Мой фокус** — актуальное рабочее направление, результат и ограничения. Он персонален и доступен AI только с разрешения владельца в релевантном target.
- **Как GPT лучше со мной взаимодействовать** — приватная настройка стиля помощи, а не биография.
- **Checkpoints** — личные точки продолжения работы; доступ через разрешённые операции, без публичной проекции.

В разделе профиля можно показывать ссылку на Home → «Мои ориентиры», но **не создавать второй редактор** этих сведений. При обычном вопросе о роли коллеги AI не должен автоматически читать его ценности, личный фокус, образование или весь журнал работ. Пользовательские принципы и guidance — данные и предпочтения, а не разрешение игнорировать системные и защитные инструкции.

## Владельцы данных и последующее развитие

**DETai Identity** владеет Account и оригиналом аватара; в перспективе — едиными личными профессиональными сведениями и контактами. **Team OS** владеет членством, командной ролью, вкладом и Home. **Sites** рендерит разрешённые публикации. **Продукты** отвечают за собственные результаты и достижения; их нельзя автоматически переносить в публичную биографию.

Сегодня часть профессиональных полей уже находится в Team OS. Этот документ **не требует сейчас мигрировать их в Identity** и не разрешает создавать второй несовместимый источник истины. Personal Profile и общая каталогизация профессиональных данных — отдельный продуктовый этап. Самостоятельно внесённое образование не становится подтверждённой DETai квалификацией; для verified claims нужны evidence и проверка. Психологические результаты и чувствительные сведения не публикуются автоматически.

## Приёмка будущего внедрения

Проверить на ограниченном synthetic/dev-контуре: новый участник без публикации; роль/описание как обязательные внутренние поля; полная Team Profile с обязательным фото; незаполненное фото не блокирует **внутренний** save; индивидуальное разрешение социальных ссылок и расширенных блоков; корректный preview; серверную очередь и статусы после реального deployment; отзыв и offboarding; приватное **первое** сохранение принципов; независимые разрешения «видно команде» / `useInAi`; сохранность ранее выбранных прав; чтение через MCP без утечки частных сведений; совместимость минимального Author Profile.

Эта страница фиксирует публично применимые правила видимости профиля; технические контракты и детали реализации остаются во внутренних документах владельца системы.
